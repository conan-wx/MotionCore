# 运动控制设计说明

## 参数和单位

核心对象使用 SI 单位；用户界面和 CSV 显示 mm、mm/s、mm/s²、mm/s³。转换只发生在 CLI/UI 边界。默认数值仿真步长为 1 ms，默认轴模型为等效质量 1 kg、阻尼 3 N·s/m、最大驱动力 20 N（各场景可覆盖）。

## 控制回路

参考位置先进入位置 P 环，得到目标速度；目标速度经限幅和斜率限制后与实际速度比较，进入速度 P/PI 环产生驱动力。驱动力再经过饱和并输入 `DynamicAxisModel`。因此目标轨迹、控制指令和实际状态在日志中是三个不同概念。

## 参数整定思路

先用开环动力学验证质量、阻尼、负载和单位，再以较小位置增益确认方向和稳定性；随后调整速度 P，最后逐步加入速度积分。积分限幅和条件积分防止饱和时 wind-up。较大增益可能让虚拟驱动力饱和，应该通过日志中的饱和标志和跟踪误差判断，而不是单纯追求更快。

## 轨迹和多轴

Phase 3 标量规划器负责时间最优约束内的 `s(t)`，Phase 4 插补器只映射同一标量路径。直线方向由几何单位向量确定；圆弧按方向计算角度并检查曲率向心项。多段路径在尖角处速度归零，避免方向突变时产生不可实现的无限加速度。

## 管理器

`MotionController` 统一管理状态机、队列、回零、限位、故障、插补、伺服和 CSV。调用者通过 `enable/home/enqueue/stop/emergency_stop/reset_fault/step` 等接口交互。核心接口即使 UI 按钮被禁用，也会再次检查状态、回零和参数。

## 验证重点

测试分别验证物理模型公式、控制器限幅和 anti-windup、规划器解析边界、几何插补、队列生命周期、动态限位以及 CSV 字段。闭环跟踪误差不能被当作规划器数值误差；规划器精度和虚拟电机性能分开报告。
